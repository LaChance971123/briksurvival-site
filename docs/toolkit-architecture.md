# Toolkit architecture — first migration pass

The free encyclopedia remains on https://ospreyzero.com. Topic toolkits and a complete preparation collection will be paid, one-time digital products delivered by Payhip. This pass creates the public publishing boundary and catalogue. No product is on sale, no price is advertised and no premium package has been produced yet.

## Public website

- `content/guides/` contains the free online editorial content. Existing guide URLs, quick answers, actions, fallback plans and sources remain.
- `content/toolkits.json` contains public sales metadata only: title, description, public component list, topic mappings, edition, price, status, collection membership and Payhip checkout identifiers.
- `/toolkits/` is the catalogue. `/toolkits/<slug>/` is a product detail page. The homepage spotlights the featured product. All guide CTAs appear after their protective instructions and sources.
- Planned products show their development status and link to details or the free guides. They do not show a Buy button, preorder or implied current price.
- Ready products require a positive price, edition, named components, a matching HTTPS Payhip direct-checkout URL and `delivery_verified: true`. Ready collections must list ready topic products. This flag records completed account-side verification; it is not proof generated by the build.
- The catalogue and featured-product pages update their availability wording from product status. Guide mappings attach a finished topic toolkit to relevant free guides without duplicating checkout data.

## Private authoring and delivery

Never create premium manuscripts, finished PDFs, ZIPs, planners, customer records or payment credentials in this public repository. Use a separate private authoring workspace. The public catalogue must not contain full premium text, download destinations, receipts or customer tokens.

The retained `scripts/document_design.py` is a reusable authoring utility, not a product generator in the website build. `make_document(..., output_dir=<absolute private path>)` requires an explicit output location outside this repository and returns a local path. Its low-level writer also rejects public-repository destinations. Product design and editorial development happen in the next phase.

Upload finished files to Payhip. Add its real checkout identifiers only after the product's payment and delivery flow is tested. The public website never authorizes a download based on a redirect, a browser flag or a hidden button. Payhip handles payment-gated access; downloaded copies cannot be made impossible to share. Download limits and eligible PDF stamping are later store-side settings, not enabled by this migration.

When using Amazon affiliate links, keep them on useful public equipment pages with disclosures. PDF shopping worksheets can link to those pages. Do not embed Amazon affiliate links or copied Amazon product data in paid PDFs. Affiliate accounts and product research are later work.

## Publishing boundary

`scripts/publication.py` constructs the route list from known free guide routes, taxonomy, product records and specific static pages. `config/public-assets.json` explicitly lists web assets. `stage_site.py` copies those individual files only; it never recursively publishes arbitrary source folders or Assets contents.

`verify_release.py` checks that the deployed file set exactly matches this allowlist, with no document/archive files or source/private folders. Public repository tracking of product documents is rejected. The existing qpdf tool archive is an explicit source-only exception and is never published. `.gitignore` adds a second safeguard; it is not access control. Anyone can still retrieve content previously published in repository history or earlier deployments. New premium work must start privately.

## Retired free access

All 185 former Osprey Zero PDF files and the portable library archive are removed from the current repository tree. The free PDF/offline generators and reader data/script are removed from the public build. Search contains free guides, trusted external references and public toolkit descriptions, without PDF resource types.

`/downloads/*` returns an explanatory 404 page. `/offline/` is a retirement notice; removed files below it return the retirement page with 404. `/offline/sw.js` remains briefly useful as a retirement worker. Existing-file shadowing preserves that worker while removed reader assets receive 404.

The retirement worker has no fetch handler, deletes only `oz-offline-` caches and unregisters itself. The shared app also attempts cleanup of only the `/offline/` registration and those caches when a visitor returns. Root `sw.js` remains the supplied Monetag worker. Devices that never reconnect and previously downloaded files cannot be remotely cleared. Ordinary browser printing/saving of free HTML is not a protected-content mechanism.

## Build and acceptance

Run `python scripts/build_site.py`. Local, Netlify and GitHub Actions use this same sequence. It builds pages, updates shared copy and metadata, stages the explicit output and verifies guide links, search intent, advertising policy, retirement scoping, catalogue lifecycle and private-file exclusion.

Before enabling the first product, confirm its exact contents and edition, upload private files to Payhip, verify purchase/receipt/redownload and unpaid access, and then mark the metadata ready. Test a real payment in addition to a delivery coupon test. Validate PDF stamping and fillable-field compatibility when those features are used.
